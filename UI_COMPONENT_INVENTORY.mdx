## Curated documentation plan

The curated proposal reduces the raw surface to **22 standalone guides** and **8 grouped family guides**: **30 first-release documentation destinations** representing approximately **70 useful element exports**. The focused `AnimateHeight` and `Hamburger` guides were created before their broader grouped guides and remain useful supplemental references.

### Decision rule

Document components that are public, reusable in Custom Components, reasonably stable, and explainable without recreating Payload internals. Group components that solve one job. Move provider-heavy surfaces to advanced references. Exclude single-use implementation details.

### Explicitly outside the first release

- **Fields:** Curate later by field family instead of creating roughly 30 isolated pages.
- **Icons:** Publish one searchable gallery instead of individual icon pages.
- **Hooks and providers:** Document by customization task in an advanced API section.
- **Localization utilities:** Keep `Translation` and `CopyLocaleData` in task-based localization documentation instead of the visual component catalog.
- **Experimental or internal exports:** Do not document as supported components until their public API is intentional. This currently includes `Combobox`.
- **Internal helpers:** Do not document unless maintainers intentionally promote them to supported public APIs.
